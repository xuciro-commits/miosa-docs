下表是本站的**块级语法**。左列是你在 Markdown 里写的形状，中间是渲染结果，右列是使用条件与失败条件。判断标准只有一条：如果去掉渲染，这段文字是否仍然读得通。

## 块级约定

| 你写的形状 | 渲染结果 | 何时用 / 何时坏 |
|---|---|---|
| `- [标题](/docs/quickstart): 一句话描述` 连续两条以上 | 导航卡片网格（两列，标题 + 描述） | 用于索引页；页面需声明 `layout: cards`。只有一条时会退化为普通列表 |
| `## 问题` 后跟答案段落（整页都是这种形状） | 手风琴（可展开、可全部展开、每条带锚点） | 用于问答页；页面前缀为 `faq/` 或声明 `layout: accordion` |
| `## 组` + 组描述 + `### 条目` + 段落 + `>` 一行 | 可折叠卡片集合（胶囊筛选 + 搜索 + 展开全部） | 用于条目多、需要按组浏览的页面；声明 `layout: collection` |
| `| 列 | 列 |` 表格 | 描边框表格，表头灰底，行分隔线 | 用于对比与参数；超过六列时改为分组或列表 |
| ` ```bash ` 代码块 | 代码框（语言标签 + 复制按钮 + 语法高亮） | 用于所有命令与示例；语言名尽量写准，`text` 用于公式与伪代码 |
| 连续两条 `**标签**` + 代码块 | 标签页（React、npm、TypeScript 等带图标） | 用于同一操作的多平台写法；少于两条时退化为普通段落 |
| ` ```mermaid ` 代码块 | 渲染成图（可点开放大） | 用于流程、时序、状态；图比文字更长时不要用 |
| `> 引用` 段落 | 引用块（左侧竖线、次级色） | 用于原文、注意、金句；不要用来放长正文 |
| `1. 步骤` 有序列表 | 步骤列表 | 用于教程；每一步只做一件事 |
| `**加粗引导**` 段落（集合卡片内） | 卡片标题 | 仅在 `layout: collection` 内有效，正文中不要用它代替标题 |
| 行内代码 `` `miosa deploy` `` | 代码 chip | 用于命令、字段名、路径；不要用于强调语气 |
| 链接 `/docs/quickstart` | 站内链接（下划线 + 悬停加深） | 用于交叉引用；外链请直接写完整 URL |

## 一个块，一个职责

同一形状只承担一种语义，这样渲染器不需要猜。反过来，如果你需要"看起来像卡片但语义是列表"，那说明这页应该换版面，而不是换写法。

## 失败案例

- 用加粗段落代替二级标题：目录（右侧"本页内容"）抓不到它，页面就少了导航。
- 用表格代替卡片网格：移动端会变成横向滚动，入口被藏起来。
- 用引用块写正文：长段落缩进后行宽变窄，阅读节奏被打断。
- 代码块语言名写成 `shell`：高亮会退化，复制按钮仍在，但读者失去颜色提示。

## 与中英对等的关系

块形状同时是结构校验的单位：中英两版必须拥有相同数量的标题、代码块与表格列。这也意味着**不能只在一边加一张表**——要么两边都加，要么换成正文描述。

具体到页面级别的分类与模板，见[页面原型](/docs/handbook/archetypes)。
